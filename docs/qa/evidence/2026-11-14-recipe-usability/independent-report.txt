Prioritized findings in the initial snapshot (post-fix outcomes below)
P1 — Unsupported unit fallback can grossly inflate portions. Deterministic evaluation inside the same isolated container, without a new model request, maps three 红烧肉 pieces to 600 g / 3027.2 kcal and four 可乐鸡翅 pieces to 800 g / 1746.1 kcal. Both use a default 200 g serving as if it were a per-piece reference. Source reproduction is saved in source_piece_conversion.json; the original HTTP cases were blocked before producing totals. Once grounding accepts these sentences, ask for edible grams when that unit lacks an explicit catalogue conversion. Do not invent a piece weight.
P1 — Helpful meal details are repeatedly converted into unknown foods. Exact known identities and weights can be extracted correctly and then blocked by phrases such as “都已经煮熟了”, “没有骨头”, or “称的是炒熟后实际吃下的净重”. The user is told the database lacks a food corresponding to their explanation. Add narrowly bounded detail grammar while preserving genuinely unknown additions. Avoid broad substring matching or dropping arbitrary clauses.
P2 — Result assumptions deserve visibility before confirmation. Case01 yields precise-looking 210.2 kcal from an assumed 200 g portion and reference ingredients. Current initial UI source puts quantity provenance and assumptions inside collapsed per-food details (renderEvidence/quantityEvidence). This is a source-based UI observation; no browser layout was inspected here. Surface a compact “reference portion/reference recipe” notice beside results, with an obvious correction/review action.
P2 — Failure wording loses the available cause distinction. Cases06,10,14 receive the same service-unavailable message. Logs show successful HKUST HTTP200 responses followed by internal AI502. Source narrows this to response envelope/finish_reason/JSON/schema/ingredient validation, but exact fields are not logged. Do not label this a demonstrated provider outage. Offer a clear retry or edit-description recovery route and retain the original meal.
P2 — Generic no-oil extraction does not remove every recipe oil. A deterministic current-container source reproduction of dish_016 / 100 g / oil_g=0 retains the reference sesame_oil 10 g per batch: 51.2 kcal. Explicit recipe_ingredients.sesame_oil=0 produces 25.9 kcal. Initial HTTP case16 was blocked, so this is a source-level failure mode, not an observed completed user result. See source_recipe_no_oil.json. Broader no-oil matching must preserve ingredient-specific semantics.
P2 — Supported household, Cantonese and no-oil descriptions remain uneven. The listed dishes in cases03,07,08,09,16 are not absent from the catalogue; surrounding ordinary language blocks matching. Selective broth consumption in case11 is different and should remain unresolved unless its actual consumed composition can be represented.
